# Data dictionary (proposed)

Metadata are for **labels, splits, and audit**. The sequence-only model can stay sequence-only.

Keep **observations** separate from **modeling labels**. Do not collapse to `peptide, label` until an explicit policy is chosen.

Retrieval from IEDB IQ-API reflects the **database at retrieval time**, not automatically the 2025-11-03 export snapshot. Store retrieval date and keep original query membership distinct from newly retrieved assay outcomes.

---

## 0. Provenance of original query membership

Grain: one row per (peptide sequence × database × pos/neg list).

| Field | Type | Meaning |
|-------|------|---------|
| peptide | string | Sequence as in `Epitope.1|Name` |
| epitope_id | int | Numeric ID from IEDB/CEDAR IRI |
| epitope_iri | string | Original IRI |
| database | `{IEDB, CEDAR}` | Which export file family |
| query_membership | `{positive, negative}` | Which 2025-11-03 list contained this ID |
| export_date | date | 2025-11-03 |
| object_type | string | Usually linear peptide |
| modifications | string | Export modification text (may be empty) |
| source_molecule_export | string | From epitope-level export |
| source_organism_export | string | From epitope-level export |
| start_export / end_export | string | Export coordinates if present |

## A. Observation table

Grain: **one row per identifiable T-cell assay** linked to an original epitope ID.

| Field | Type | Decision it supports |
|-------|------|----------------------|
| observation_id | string | `IEDB_ASSAY:{tcell_id}` |
| tcell_id | int | IEDB assay identifier |
| queried_epitope_id | int | Original export ID used in the API query |
| returned_structure_id | int | `structure_id` on the returned assay |
| export_peptide | string | Peptide string from the 2025-11-03 pool |
| linear_sequence | string | Sequence on the assay record |
| sequence_matches_export | bool | Whether it matches the 2025-11-03 peptide string |
| e_modification | string | Modification/structure text if the API returns it |
| qualitative_measure | string | Positive / Negative / Positive-Low / etc. |
| outcome_family | `{positive, negative, other, missing}` | Prefix family only; not a modeling label |
| assay_names | string | Exact endpoint/subtype string |
| endpoint_family | `{functional_response, recognition_binding, structural, other_or_unresolved}` | Dictionary flag; do not pick a winner by model score |
| assay_description | string | Curated assay text |
| host_organism_name | string | **Assay host**, not source organism |
| host_organism_iri | string | |
| host_is_human | 0/1 | Homo sapiens only. HLA-transgenic mouse remains mouse |
| host_is_transgenic_mouse | 0/1 | |
| mhc_class | `{I, II, non classical, null}` | Class I eligibility |
| mhc_allele_name | string | Raw restricting-element text. Do not normalize `HLA-A2` → `HLA-A*02:01` |
| mhc_restriction | string | |
| mhc_allele_evidence | string | How restriction was assigned |
| mhc_annotation_present | 0/1 | Field presence, not usable-allele status |
| mhc_specificity | `{missing, class_only, serotype, allele, other}` | Resolution of the raw string |
| mhc_modified_experiment | 0/1 | Mutant/substitution language in allele or restriction text |
| mhc_evidence_category | string | Coarse bucket of `mhc_allele_evidence` |
| reference_id | int | Study grouping |
| reference_iri | string | |
| pubmed_id | string | |
| immunization_description | string | Stimulation / exposure context |
| direct_ex_vivo_bool | 0/1/null | `0` is recorded, not missing |
| parent_source_antigen_name | string | Antigen-level grouping |
| source_organism_name | string | Peptide source organism |
| retrieval_time_utc | datetime | When IQ-API was queried |
| retrieval_source | string | `iedb_query_api.tcell_search` |

**Not modeling features:** qualitative_measure, assay outcome, endpoint_family, and any field generated by the experiment.

Distinct `tcell_id` values are distinct curated records, not independent biological replicates. Same recorded context is not the same experiment.

## B. Modeling table (versioned view)

Grain: one row per peptide **after** an explicit eligibility + aggregation policy.

V1 policy (already frozen): valid standard AA; drop if in both pos and neg lists; keep first duplicate; length 8–11; stratified random split.

Later policies are new versions (`V2_...`). Do **not** silently replace V1.

| Field | Type | Meaning |
|-------|------|---------|
| peptide | string | |
| in_iedb / in_cedar | bool | Database membership (not exclusive source) |
| in_iedb_pos / in_iedb_neg | bool | Original query membership |
| in_cedar_pos / in_cedar_neg | bool | |
| v1_conflict | bool | Historical: present in both 2025-11-03 pos and neg lists. Not an intrinsic property of the sequence |
| current_all_observation_conflict | bool | Mixed positive/negative among all recovered current-DB assays |
| task_observation_conflict | bool | Mixed **inside a named eligibility subset**; may differ from the two fields above |
| v1_retained | bool | Survived V1 conflict+AA rules (any length) |
| v1_in_modeling_set | bool | Length 8–11 and V1-retained |
| v1_partition | `{train, test, not_in_v1}` | |
| epitope_ids | list[int] | All original IDs for this sequence |
| n_tcell_assays_retrieved | int | From observation table (current DB) |
| n_pos_assays / n_neg_assays | int | Current-DB counts; may differ from 2025 lists |
| hosts | list | Distinct assay hosts |
| mhc_classes | list | Distinct annotated classes |
| n_studies | int | Distinct `reference_id` |
| modeling_label | 0/1/null | **Only after a named policy** |
| policy_id | string | e.g. `v1_query_membership_drop_conflicts` |

Replace the V1 `source=IEDB` field with `in_iedb` / `in_cedar`. After V1 dedupe, `source` only records which duplicate was kept.

CEDAR supplied overlapping records and participated in conflict handling; it did not contribute additional retained unique peptides after the documented cleaning stages.

## Policies not chosen yet

These each define a different learning problem. Do not switch automatically:

- any-positive-wins
- majority vote
- require repeated negatives
- restrict to human hosts
- restrict to MHC class I
- restrict to one assay endpoint

Choose after inspecting observation coverage (pilot, then full retrieval).

Candidate subsets used in Stage-1 descriptive tables (`human`, `human + class I`, `human + class I + functional`, plus exact endpoint and restriction-evidence splits) are **illustrative**. They are not V2. Outcome patterns in those tables are `positive_only`, `negative_only`, `mixed`, and `insufficient_unknown` (no eligible evidence, or no positive/negative outcome family).
